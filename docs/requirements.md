# 1. プロジェクト概要

## 1.1 アプリ名

**Decaf Log**

## 1.2 アプリ概要

Decaf Logは、ユーザーが日々摂取したカフェイン量を記録し、摂取量を把握することで、カフェイン摂取量の削減を支援するWebアプリである。

ユーザーは飲み物・カフェイン量・摂取日時を登録し、履歴や当日の合計摂取量を確認できる。

将来的には目標管理、グラフ、連続達成日数などを追加する。

## 1.3 開発目的

本プロジェクトの最優先目的は、

**実際に動作するWebアプリを完成させ、公開すること**

である。

プログラミング学習を目的とした過度な分割、冗長なコード、教育目的の実装は不要。

以下を重視する。

- シンプルな実装
- 安定動作
- 保守しやすい構成
- モバイルでの使いやすさ
- 必要十分なテスト
- MVPスコープの厳守
- デプロイ可能な状態

# 9. 機能要件

## FR-001 カフェイン摂取記録登録

ユーザーは以下を入力して記録できる。

- 飲み物名
- カフェイン量
- 摂取日時

### 飲み物名

必須。

文字列として保存する。

前後の不要な空白は除去する。

### カフェイン量

必須。

単位：

`mg`

0以上の数値のみ許可する。

負数は登録不可。

### 摂取日時

ユーザーが入力可能。

初期値は現在日時。

未設定の場合は現在日時を利用してもよい。

---

# 10. FR-002 データ保存

正常な入力内容をSupabaseへ保存する。

保存成功後：

1. 登録処理を完了する
2. ユーザーへ成功したことが分かる状態にする
3. ダッシュボードへ戻る
4. 新しい記録が画面へ反映される

登録失敗時：

- 入力内容を可能な限り保持する
- エラーメッセージを表示する

---

# 11. FR-003 履歴表示

Supabaseに保存されている記録を一覧表示する。

並び順：

**摂取日時の新しい順**

表示項目：

- 摂取日
- 摂取時刻
- 飲み物名
- カフェイン量
- 削除操作

---

# 12. FR-004 記録削除

履歴から記録を削除できる。

削除処理前にユーザーへ確認する。

削除成功後：

- Supabaseから削除される
- UIから対象データが消える
- 今日の合計値も再計算される

削除失敗時：

- 元の記録は画面上に残す
- エラーメッセージを表示する

---

# 13. FR-005 今日のカフェイン合計

当日のカフェイン摂取量を合計する。

対象：

ユーザーのローカル日付における当日分。

計算：

```text
当日の全 caffeine_mg の合計
```

例：

```text
コーヒー 100mg
緑茶      30mg
```

結果：

```text
130mg
```

ダッシュボードに大きく表示する。

記録がない場合：

```text
0mg
```

と表示する。

## FR-006 カフェイン目標設定

ユーザーは1日のカフェイン摂取目標値を設定できる。

### 目標値

単位：

`mg`

1. 保存処理を完了する

## Version 1.1 データベース（app_settings）

テーブル名：

```text
app_settings
```

### 必須カラム

| カラム | 型の想定 | 必須 | 内容 |
| --- | --- | ---: | --- |
| `id` | smallint | Yes | 固定値 `1`（Primary Key） |
| `daily_caffeine_goal_mg` | numeric | No（NULL許可） | 1日のカフェイン目標値。未設定は`NULL` |
| `updated_at` | timestamptz | Yes | 更新日時 |

### 制約

`app_settings` はアプリ全体で常に1行のみとする。

`id` はランダムなuuidではなく固定値とする。

```sql
id smallint primary key default 1 check (id = 1)
```

初期行（`id = 1`）はSupabaseのmigration/schema適用時に1件のみ作成する。アプリケーションコードから `app_settings` へのINSERTは行わない（SELECT / UPDATEのみを行う）。

`daily_caffeine_goal_mg` はNULLを許可し、NULLまたは0以上の数値のみを許可する。

```sql
check (daily_caffeine_goal_mg is null or daily_caffeine_goal_mg >= 0)
```

`updated_at` はアプリ側で保存時に現在時刻を設定する。

既存の `caffeine_records` テーブル・RLS・GRANTには変更を加えない。

DB変更は `supabase/migrations/` 配下にVersion 1.1用のmigration SQLとして追加し、`supabase/schema.sql` にも現在のDB全体の完成形として `app_settings` の定義を反映する。

## Version 1.1 Supabaseセキュリティ（app_settings）

`app_settings` もMVPと同様、認証機能を前提としない。

anonロールへの権限は以下の通りとする。

| 操作 | 許可 |
| --- | --- |
| SELECT | 許可 |
| UPDATE | 許可 |
| INSERT | 不許可 |
| DELETE | 不許可 |

初期行（`id = 1`）はSupabaseのmigration/schema適用時に作成し、アプリケーションコードからの `app_settings` へのINSERTは行わない。

RLSは無効化せず、必要最小限のポリシーのみを設定する。

既存の `caffeine_records` のRLS・GRANTには変更を加えない。

## FR-008 目標進捗表示

ダッシュボードに、今日のカフェイン合計（FR-005）と1日のカフェイン目標値（FR-006, `daily_caffeine_goal_mg`）を用いた進捗表示を追加する。

**進捗表示の位置づけ：** Decaf Logはカフェイン摂取量の「削減」を支援するアプリである。そのため、一般的な「達成率」の進捗バーのように、値が増える・バーが満ちるほど良いという意味にはしない。この進捗表示は「1日のカフェイン目標上限にどれだけ近づいているか」を示すものとする。

### 目標未設定（`NULL`）の場合の表示

目標が未設定の場合、進捗バーは表示しない。代わりに以下を表示する。

```text
1日の目標が設定されていません。
```

あわせて、`/settings` への導線として次を表示する。

```text
目標を設定する
```

### 通常時の表示（目標が1以上に設定されている場合）

以下の情報が分かる表示を基本とする。

```text
今日 100mg
目標 200mg
50%
あと100mg
```

- 今日の摂取量（`todayTotalMg`）
- 設定済みの目標値（`daily_caffeine_goal_mg`）
- 進捗率（%）
- 残り摂取可能量（mg）（`目標値 - 今日の摂取量`。0以上の場合）

進捗バーの視覚的な幅は最大100%で止める（100%を超えても画面外にはみ出さない）。

### 目標に到達した場合（今日の摂取量＝目標値）

```text
目標上限に達しました
```

と表示する。

### 目標を超過した場合（今日の摂取量＞目標値）

進捗率の数値は実際の値をそのまま表示する。

例：250mg / 200mg → 130%ではなく **125%**

進捗バーの視覚的な幅は、超過時も最大100%で止める。

超過分が分かる文言を表示する。

例：

```text
目標を50mg超えています
```

進捗率が100%以上の場合は、100%未満の通常状態と視覚的に区別できる警告表示とする（色などによるシンプルな区別。大きなデザイン変更や複雑なアニメーションは不要）。

### 目標が0mgの場合

0での除算は行わない。`NaN`や`Infinity`が画面に表示されないようにする。

- 今日の摂取量が0mgの場合：「カフェイン摂取なし」「目標内」に相当する表示とする（進捗率(%)は表示しない）
- 今日の摂取量が1mg以上の場合：「目標を超えています」と表示する（進捗率(%)は表示しない）

`caffeine_records`の取得（今日の合計・最近の記録）が成功している場合は、以下を通常どおり表示する。

- 今日のカフェイン合計
- 最近の記録

目標進捗部分（`app_settings`の取得に依存する部分）のみ、以下を表示する。

```text
目標を取得できませんでした。
```

## FR-010 連続達成日数

ダッシュボード（`/`）に、目標に対する連続達成日数を表示する。

### 達成の定義

その日の合計摂取量（`dailyTotalMg`）が、`daily_caffeine_goal_mg`（以下、目標値）以下の場合を「達成」とする。

```text
dailyTotalMg <= goalMg  → 達成
dailyTotalMg >  goalMg  → 未達成
```

目標0mgの場合も、上記の比較ルールをそのまま適用する（その日の合計が0mgなら達成、1mg以上なら未達成。Version 1.2のFR-008と同じ意味）。

### 判定対象期間

**今日は連続達成日数の判定に含めない。** 今日はまだ一日が終了しておらず、最終的な達成判定ができないため、判定は**昨日まで**を基準とする。

昨日から過去方向へ、連続して達成している日数を数える。

判定は以下のいずれかに到達した時点で終了する。

- 最初の未達成日に到達した場合
- `caffeine_records`に存在する最初の記録日より前に到達した場合（それより前の日付は判定対象に含めない）

`caffeine_records`に一度も記録が存在しない場合、連続達成日数は0日とする。

### 記録がない日の扱い

判定対象期間内で記録がない日は0mgとして扱う（Version 1.3のFR-009における日別集計ルールと同様）。同じ日に複数記録がある場合は合算した上で目標値と比較する。

### 目標未設定（`NULL`）時の表示

目標が未設定の場合、連続達成日数を「0日」とは表示しない。代わりに以下を表示する。

```text

目標を設定すると連続達成日数を確認できます。

目標を設定する
```

「目標を設定する」は`/settings`への導線とする（Version 1.2のFR-008における「目標を設定する」導線と表現・UIを揃える）。

### 連続達成日数が0日の場合の表示
