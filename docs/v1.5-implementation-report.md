## 2. 実装した機能

- FR-011：`/record`（カフェイン記録画面）への飲み物プリセット（chip形式のボタン、6種類）の追加
  - プリセットボタンを押すと、「飲み物」（`drinkName`）と「カフェイン量」（`caffeineMg`）へ対応する値をセットする
  - プリセット選択後も、「飲み物」「カフェイン量」を自由に手動編集できる
  - 「※カフェイン量は目安です。選択後に変更できます。」という注意書きを表示する
  - 専用の「その他／手入力」ボタンは追加せず、プリセットを選ばなければ従来通り手入力できる
  - スマートフォン幅ではプリセットボタンが自然に折り返され、横スクロールは発生しない

`docs/requirements.md`・`docs/screen-design.md`のVersion 1.5受け入れ条件（FR-011関連・§79〜§85）はすべて満たしている。

## 3. 6種類のプリセット内容

| 飲み物 | カフェイン量の目安 |
| --- | --- |
| コーヒー | 90mg |
| 緑茶 | 30mg |
| 紅茶 | 30mg |
| 烏龍茶 | 20mg |
| エナジードリンク | 100mg |
| コーラ | 35mg |

すべて整数mgで、`src/lib/drinkPresets.js`にフロントエンドの定数（`DRINK_PRESETS`）として定義している。DBには保存していない。

## 4. プリセットが入力ショートカットであること

プリセットは「飲み物」「カフェイン量」の初期値を自動入力するだけの**単純な入力ショートカット**として実装した。

- 「現在選択中のプリセット」を表すstateは持たない
- 選択中プリセットの視覚的なハイライトは行わない
- 入力値を変更した際にプリセットとの同期を取る処理（選択解除など）も実装していない
- プリセットボタンを押すたびに、その時点の`drinkName`・`caffeineMg`を上書きするだけであり、以降は通常の入力欄として自由に編集できる
- 既存の`validate`・`handleSubmit`・`insertRecord`のロジックは一切変更していない。プリセットで入力された値も、手入力された値と全く同じフィールド・同じ検証ルールで扱われる

## 14. 既知の制約

- **プリセットのカフェイン量は目安値である。** 商品・容量・抽出方法等によって実際のカフェイン量は異なる
- **プリセットは固定6種類（コーヒー・緑茶・紅茶・烏龍茶・エナジードリンク・コーラ）である。** ユーザー独自プリセットの追加・編集はできない
- **プリセットはDBではなくフロントエンドの定数として保持している。** 将来的にプリセット内容を変更する場合はソースコードの変更（`src/lib/drinkPresets.js`）が必要になる
- Version 1.0〜1.4から引き続く制約（認証なし、`caffeine_records`のRLSがMVP/デモ用途の暫定構成、記録編集不可、目標値履歴なし、Rechartsによるバンドルサイズ増加など）は変更なし。詳細は`docs/mvp-implementation-report.md` §9、`docs/v1.1-implementation-report.md` §10、`docs/v1.2-implementation-report.md` §10、`docs/v1.3-implementation-report.md` §13、`docs/v1.4-implementation-report.md` §13を参照

## 15. 今後の拡張候補

`docs/requirements.md` §28ではVersion 1.5が現時点でのロードマップの最終項目であり、Version 1.6以降の具体的な機能はまだ定義されていない。今後の拡張候補として考えられるもの（あくまで候補であり、着手が決まっているものではない）：

- 記録編集機能（現状は削除して登録し直す運用）
- ユーザー独自のプリセット管理（追加・編集・削除）。実装する場合は新しいDBテーブル・RLS・GRANTの設計が必要になる
- 目標値の履歴管理（Version 1.4の既知の制約の解消）
- ユーザー認証（複数ユーザー対応、`caffeine_records`のRLSを本人の行のみ操作可能な構成へ変更）
- 通知、SNS連携、ダークモードなど（`docs/requirements.md` §7に記載のMVP対象外機能）

各Versionは「実装 → テスト → 既存機能確認 → コミット」の順で進める方針（`docs/requirements.md` §28）を今後も踏襲する。
