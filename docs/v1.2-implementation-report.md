## 2. 実装済み機能

- FR-008：ダッシュボードへの目標進捗表示
  - 今日のカフェイン摂取量・目標値・進捗率（%）・残り摂取可能量（mg）を表示
  - 目標未設定（`NULL`）時：進捗バーを表示せず、「1日の目標が設定されていません。」と`/settings`への導線（「目標を設定する」）を表示
  - 目標到達時（今日の摂取量＝目標値）：「目標上限に達しました」と表示
  - 目標超過時（今日の摂取量＞目標値）：実際の進捗率（例：125%）と「目標を◯mg超えています」を表示し、警告状態の配色にする（バーの視覚的な幅は100%で頭打ち）
  - 目標0mg時：0除算をせず、`NaN`/`Infinity`を表示しない。摂取0mgなら「カフェイン摂取なし」相当、1mg以上なら「目標を超えています」（進捗率は非表示）
  - 目標値の取得中・取得失敗時も、今日の合計・最近の記録の表示をブロックしない独立設計
  - 進捗バーへの`role="progressbar"`, `aria-valuemin`, `aria-valuemax`, `aria-valuenow`の付与
- **status判定は丸め後の`percent`ではなく、`todayTotalMg`と`goalMg`の実際の値の比較で行う**（199.6mg/200mg→`normal`、200mg/200mg→`reached`、200.4mg/200mg→`exceeded`。丸め誤差による境界の誤判定を防止）
- 進捗表示は「達成率」ではなく「1日のカフェイン目標上限にどれだけ近づいているか」を表すものとして実装（配色は100%未満＝通常、100%以上＝警告のみのシンプルな区別）

`docs/requirements.md`・`docs/screen-design.md`のVersion 1.2受け入れ条件、および`docs/implementation-plan-v1.2.md` §19はすべて満たしている。

## 10. 既知の制約

- Version 1.0 / 1.1から引き続く制約（認証なし、`caffeine_records`のRLSがMVP/デモ用途の暫定構成、記録編集不可、履歴の日付グループ非対応、同時保存の競合制御なしなど）は変更なし。詳細は`docs/mvp-implementation-report.md` §9、`docs/v1.1-implementation-report.md` §10を参照。
- 進捗率の表示は四捨五入した値であり、`status`（`normal`/`reached`/`exceeded`）の判定とは独立している。そのため、表示上「100%」であっても`status`が`normal`のまま（例：199.6mg/200mg）というケースが起こり得る（意図した仕様。§2参照）。
- Vercel PreviewもProductionと同じSupabaseプロジェクトを参照する。Preview確認時に一時的に変更した目標値は、確認後に元の値へ戻す運用とした（`docs/implementation-plan-v1.2.md` §18）。
