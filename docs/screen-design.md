# Decaf Log 画面設計書

## 0. この文書の目的

本書は、`requirements.md` に定義された機能を、React上でどのような画面として実装するかを定義する。

Claude CodeはUI実装前に、

```text
docs/requirements.md
docs/screen-design.md
```

の両方を確認すること。

機能仕様について矛盾がある場合は `requirements.md` を優先する。

---

# 1. MVP画面一覧

Version 1.0では以下の3画面を実装する。

| ID      | URL        | 画面           |
| ------- | ---------- | -------------- |
| SCR-001 | `/`        | ダッシュボード |
| SCR-002 | `/record`  | カフェイン記録 |
| SCR-003 | `/history` | 摂取履歴       |

以下はMVPでは実装しない。

```text
/settings
```

設定画面はVersion 1.1以降。

# 3. 共通レイアウト

## Header

全画面上部に表示。

表示内容：

```text
Decaf Log
```

MVPでは複雑なロゴを用意する必要はない。

アプリ名が明確に認識できればよい。

---

# 4. Bottom Navigation

全主要画面で使用する。

項目：

```text
ホーム
記録
履歴
```

遷移：

```text
ホーム
→ /

記録
→ /record

履歴
→ /history
```

現在表示中の項目は他の項目と区別できるようにする。

React Routerの `NavLink` 等を利用してよい。

モバイルでは画面下部へ固定してよい。

ただしコンテンツがBottom Navigationの裏へ隠れないこと。

---

# 5. UI基本方針

キーワード：

```text
シンプル
落ち着いている
清潔感
読みやすい
操作しやすい
```

以下を優先する。

1. 今日の摂取量が分かる
2. 記録ボタンがすぐ見つかる
3. 履歴が読みやすい
4. フォームが入力しやすい

不要な装飾や高度なアニメーションは実装しない。



```text

```

- 時刻


# 27. 表示順

履歴は、

```text
consumed_at DESC
```

とする。

つまり、

**新しい記録を上に表示する。**

---

# 28. 記録表示項目

1レコードにつき以下を表示する。

- 飲み物名
- カフェイン量
- 摂取日
- 摂取時刻
- 削除操作

例：

```text
コーヒー

100mg

10:00

削除
```

---

# 29. 日付グループ

可能であれば日付ごとにまとめて表示する。

例：

```text
2026/09/12

コーヒー   100mg   10:00
緑茶        30mg   15:00


2026/09/11

コーヒー   100mg   09:30
```

ただし、実装が過度に複雑になる場合、MVPでは単純な一覧表示でも要件を満たす。

日付グループはMVP完成を妨げてはならない。

---

# 30. 削除操作

各記録へ、

```text
削除
```

を設置する。

削除操作前に確認を行う。

例：

```text
この記録を削除しますか？
```

選択肢：

```text
キャンセル

削除
```

MVPでは `window.confirm()` を使用してもよい。

---

# 31. 削除成功

成功した場合：

- 対象記録を画面から削除
- Supabase上から削除
- ダッシュボードの合計値へ反映

必要であれば、

```text
記録を削除しました。
```

を短時間表示してよい。

---

```text
記録の削除に失敗しました。
もう一度お試しください。
```

元の記録は画面上に残す。

最低限以下を守る。

# 52. 設定画面 Loading / Error状態

## Loading

`/settings` を開いた際、保存済みの目標値取得中は、

```text
読み込み中...
```

を表示する。

## Error（取得失敗）

```text
データの取得に失敗しました。
もう一度お試しください。
```

## Error（保存失敗）

```text
設定の保存に失敗しました。
もう一度お試しください。
```

入力内容は画面上に保持する。

## Empty

設定画面にEmpty状態は設けない。目標値が未設定の場合も入力欄が空欄で表示されるため、画面自体が空白になることはない。

---

# 53. 設定画面のキャンセルボタンについて

`/settings` 画面に「キャンセル」ボタンは配置しない。

記録画面（`/record`）と異なり、設定画面は特定の入力フローの途中で離脱するような画面ではないため、他画面への移動は共通のBottom Navigationのみを手段とする。

# 70. 記録がない日・記録が0件の場合の表示

- 履歴一覧側の既存Empty状態（「まだ記録がありません。」＋「＋ カフェインを記録」導線）は変更しない。グラフとリストは独立した表示であり、リストがEmpty状態のときもグラフ自体は7日分の0mg表示を行う

# 85. Version 1.5 画面受け入れ条件

## 記録画面（プリセットボタン）

- [ ] `/record`にプリセットボタン（コーヒー・緑茶・紅茶・烏龍茶・エナジードリンク・コーラの6種類）が表示される
- [ ] プリセットボタンを押すと、「飲み物」「カフェイン量」へ対応する値がセットされる
- [ ] プリセット選択後も、「飲み物」「カフェイン量」を自由に編集できる
- [ ] プリセットを使わず、従来通り手入力のみで記録を登録できる
- [ ] 「※カフェイン量は目安です。選択後に変更できます。」という注意書きが表示される
- [ ] スマートフォン幅でプリセットボタンが自然に折り返され、横スクロールが発生しない
- [ ] 既存の入力バリデーション・登録処理・キャンセル処理に変更がない
