## 3. データベース変更案

新規テーブル `app_settings` を追加する（既存の `caffeine_records` は変更しない）。

```sql
create table if not exists public.app_settings (
  id uuid primary key default gen_random_uuid(),
  daily_caffeine_goal_mg numeric not null check (daily_caffeine_goal_mg >= 0),
  updated_at timestamptz not null default now()
);
```

- ユーザー提示の3カラム（`id`, `daily_caffeine_goal_mg`, `updated_at`）をそのまま採用
- MVP同様、認証なし・単一ユーザー前提のため `user_id` は追加しない
- **単一行（シングルトン）運用**を想定：アプリは複数ユーザーの目標を管理しないため、テーブルには常に1行のみ存在する想定
  - **案A（推奨）**：`supabase/schema.sql` 適用時に初期値（例：0mg）の行を1件INSERTしておき、アプリ側は常にSELECT/UPDATEのみ行う（INSERTはしない）
  - **案B**：アプリ側が「行が存在しなければINSERT、存在すればUPDATE」を行う（upsert）
  - 案Aの方がanonへ付与する権限を少なく抑えられるため推奨（§7で確認）
- `updated_at` はDBトリガーを追加せず、アプリ側で保存時に現在時刻をセットする方針（トリガー追加による複雑化を避ける）

## 4. RLS / GRANT方針

`caffeine_records` と同様にRLSは有効のまま、必要最小限の権限のみ付与する。

```sql
alter table public.app_settings enable row level security;

-- 案Aを採用する場合、anonにはSELECTとUPDATEのみ付与（INSERT・DELETEは不要）
grant select, update
on table public.app_settings
to anon;

revoke insert, delete
on table public.app_settings
from anon;

create policy "Allow public read access to app_settings"
on public.app_settings
for select
to anon
using (true);

create policy "Allow public update access to app_settings"
on public.app_settings
for update
to anon
using (true)
with check (daily_caffeine_goal_mg >= 0);
```

- `caffeine_records`（SELECT/INSERT/DELETE許可）よりもさらに権限を絞れる（INSERT・DELETE不要）ため、案Aを採用できればセキュリティ上望ましい
- 案B（アプリ側upsert）を選ぶ場合は `insert` 権限も追加で必要になる
- 既存の `caffeine_records` のRLS・GRANTは変更しない

## 7. 不明点・判断が必要な点（実装前にユーザー確認が必要）

1. **単一行テーブルの管理方法**：§3の案A（schema.sql側で初期行を1件INSERTし、アプリはSELECT/UPDATEのみ）を採用してよいか。案Bにする場合はanonへのINSERT権限追加が必要になる。
2. **目標値未設定時の挙動**：初回アクセス時に目標値が0であることを「未設定」として扱うか、それとも「0mgが目標として設定されている」状態として扱うか。案Aを採用する場合、初期値は何mgにしておくか（0mgを想定しているが要確認）。
3. **保存成功時のUI挙動**：カフェイン記録画面（`/record`）は保存成功後に `/` へ遷移するが、設定画面は一般的に「同じ画面に留まり、保存済みメッセージを表示する」方が自然と考えている。この理解で良いか。
4. **ダッシュボードへの目標値表示の要否**：今回の想定仕様には含まれていないが、Version 1.1で目標値をダッシュボードに（プログレスバーなしで）テキスト表示するかどうか。screen-design.mdの現状は「進捗バー等はMVPでは表示しない」としているだけで、Version 1.1での扱いは明記されていないため確認したい。
5. **設定画面に「キャンセル」ボタンが必要か**：記録画面と異なり、遷移を伴わない単純なフォームのため、保存ボタンのみで良いか、それとも他画面へ戻る導線が必要か。
